# Rejection records

Lit records own rejection decisions. Put the substantive reason, evidence,
related issue references, and any reconsideration on the issue itself. Use native
related links where useful, and fetch current records after grep discovery.

Existing `.out-of-scope/` documents are historical context. Read relevant entries
without treating them as binding current decisions. Do not create, update, delete,
or require this second database as part of triage. If an old decision conflicts
with current direction, surface that conflict; record the new disposition in lit.

Distinguish rejected scope from already implemented behavior and duplicates. An
already implemented outcome needs concrete implementation evidence; a duplicate
needs a related tracker reference. Reconsideration does not silently reopen prior
issues. Explicit user directions govern status; otherwise an agreed wontfix
rejection includes a reason comment and closure.
